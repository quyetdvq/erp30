# P1-API-003 Common List Query Adapter Assessment

## Outcome

Implemented the reusable common list/search/filter/sort/pagination transport
adapter. No business endpoint, schema, export format, frontend UI, or
OpenAPI operation was added. This corrective follow-up changes only the
collection metadata transport type for `total`.

## Components

- `CommonListQueryAllowlist`: endpoint-owned search, filter, and sort field
  allowlists with validated field names.
- `CommonListQueryAdapter`: canonical query parsing and pagination defaults/
  limits; malformed syntax and unknown fields raise the framework 400 error.
- `CommonListQuery`: immutable normalized query containing search text and
  fields, scalar/repeated filter values, validated sort terms, page, size, and
  offset.
- `CommonListSortTerm`: explicit ASC/DESC transport term.
- `AuthorizedListSource`: the only source boundary exposes
  `countAuthorized()` and `fetchAuthorized()`; the adapter has no unscoped
  count/list path.
- `CommonListResult`: normalized non-negative string count internally plus
  authorized rows.
- `ApiTransport::collection()`: collection envelope with numeric page,
  page_size, and total metadata, plus API-001 request ID/serialization
  behavior.

## Contract checks

## Corrective Runtime Check

- Before: `ApiTransport::collection()` explicitly cast `total` to `string`,
  and the prior focused test asserted a string total.
- After: collection metadata emits `page`, `page_size`, and `total` as JSON
  integers; `request_id` remains a string. The focused runtime assertions
  cover `total=0`, nonzero total, and a BIGINT entity `id` remaining a string.

- Canonical keys: `q`, `page`, `page_size`, `sort`, `filter[field]`, and
  repeated `filter[field][]` values.
- Defaults: page `1`, page size `50`; maximum page size `200`.
- Sort grammar: comma-separated `field`/`-field`; malformed, duplicate, or
  unknown terms are rejected with 400. `id ASC` is appended when absent.
- Filters are normalized to lists of strings; nested associative values,
  empty lists, unknown fields, and malformed top-level keys are rejected.
- Endpoint search/filter/sort allowlists are explicit; no arbitrary SQL field
  or operator is accepted.
- Authorization/data-scope responsibility remains in the source. Both total
  and rows are obtained through the authorized source boundary, preserving the
  same scope for future selector/list use.
- Collection metadata `page`, `page_size`, and `total` are JSON integers;
  `request_id` remains a string. Entity BIGINT identifier keys and decimal
  values remain transport-safe strings, and the existing request ID is
  preserved/generated by API-001.
